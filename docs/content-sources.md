# Infrastructure content direction

The owner confirmed the headline's infrastructure/cloud theme for the underground story. The three tiles and Verdant comparison column are proposed brand messaging for this website concept; no performance metrics, pricing or compliance claims are made.

The general public-cloud/on-premises distinction in the table follows primary references:

- AWS, Cloud vs. On-Premises: infrastructure location, ownership and maintenance. https://aws.amazon.com/what-is/cloud-vs-on-premises/
- AWS overview: on-demand cloud resources and services. https://docs.aws.amazon.com/whitepapers/latest/aws-overview/what-is-cloud-computing.html
- Google Distributed Cloud overview: cloud-style tooling can operate on a company's own physical infrastructure. https://docs.cloud.google.com/kubernetes-engine/distributed-cloud/bare-metal/docs/concepts/about-bare-metal

Traditional on-premises provisioning is described as stack-dependent, avoiding an assumption that all on-premises systems are manual. Local growth is tied to adding physical resources, not unlimited elasticity.

The owner requested that the feedback button have no destination for this iteration.

The numeric rows are an explicitly illustrative configuration, not measured Verdant specifications. The comparison assumes 96 vCPU in each model, with three local servers/nodes for the two on-premises examples and no on-site servers for the public-cloud example. Visible example labels and the configuration note keep these numbers distinct from product claims.
